# Поток — персональные финансы

Готовое одностраничное приложение на HTML, CSS и Vanilla JavaScript. Без сборки, базы на сервере, регистрации и аналитических трекеров. Валюта — российский рубль. Деньги хранятся целыми копейками; выражения рассчитываются без `eval`.

## Быстрый старт

1. Откройте приложение через HTTPS или локальный веб-сервер.
2. В «Обзор → Мои счета → Управлять» укажите начальные остатки. На телефоне настройки доступны через шестеренку вверху.
3. Запишите первую операцию. Можно ввести `350 + 120`, `1000 / 3` или `(250 + 150) * 2`.
4. В «Планы» добавьте подписки, постоянные доходы, цели и долги. Для ежемесячных шаблонов выберите автоматическую запись или ручное подтверждение. Это только учет: приложение не переводит реальные деньги и не подключается к банку.
5. Регулярно скачивайте JSON в настройках.

Кнопка «Демоданные» включает отдельную временную базу с вымышленными цифрами. Ваши записи сохраняются отдельно. Выход и перезагрузка возвращают собственную базу.

## GitHub Pages

1. Создайте репозиторий и загрузите **содержимое этой папки** в корень ветки `main`.
2. В GitHub откройте Settings → Pages → Deploy from a branch → `main` → `/ (root)` → Save.
3. Откройте выданный GitHub адрес по HTTPS. Все пути относительные: приложение работает и по адресу `https://username.github.io/repository/`.
4. Для установки на Android выберите в меню браузера «Установить приложение». На iPhone в Safari: «Поделиться» → «На экран Домой».

GitHub Pages не требует `npm`, сборщика или настроек сервера. `.nojekyll` исключает ненужную обработку файлов.

Для локального запуска, если установлен Python:

```sh
python3 -m http.server 8000
```

Откройте `http://localhost:8000`. Открытие `index.html` двойным щелчком через `file://` не поддерживается: ES-модули и PWA требуют HTTP/HTTPS.

## Что умеет

- Быстрая запись доходов, расходов и переводов с калькулятором, датой, заметкой и запоминаемыми тегами.
- Несколько счетов с отдельными остатками; категории и счета можно добавлять и переименовывать.
- Контуры «Личное» и «Дело». Баланс фильтруется по принадлежности счета; доходы и расходы — по контуру операции. Рабочую покупку можно оплатить личной картой.
- Дневной бюджет с резервом на регулярные платежи и общим месячным лимитом.
- Ежемесячные расходы и доходы с датой начала, категорией и автоматическим либо ручным режимом.
- Частичные погашения долгов с неизменной общей суммой, остатком и историей каждого платежа.
- Накопительные цели и безопасный сброс офлайн-кэша без удаления финансовой базы.
- Диаграммы Chart.js, доля сохраненного дохода, сравнение шести месяцев.
- Поиск и фильтры по истории, редактирование и удаление операций.
- Экспорт всей базы в JSON, проверяемый импорт с подтверждением замены, CSV с текущими фильтрами для Excel.
- PWA с иконками, ярлыками быстрого запуска и офлайн-кэшем.

## Как считаются деньги

Баланс счета = начальный остаток + доходы − расходы − переводы со счета + переводы на счет − пополнения целей. Операции с будущей датой не меняют доступный баланс до наступления этой даты. Переводы и пополнения целей не участвуют в доходах/расходах и Savings Rate.

Дневной бюджет = `max(0, доступный баланс − резерв) / дни до конца месяца`, с округлением вниз до копейки. Текущий день включен. Если задан месячный лимит, для контура «Все финансы» применяется меньшая из двух сумм: доступные деньги и остаток лимита после фактических расходов; из нее также вычитается резерв. Для отдельных контуров общий лимит не применяется. Период графиков не меняет дневной бюджет текущего месяца.

Резерв — сумма еще не записанных ежемесячных расходов текущего месяца. Просроченный расход остается в резерве до конца месяца. Запись из шаблона снимает его резерв за соответствующий месяц. Регулярные доходы в резерв не входят и не увеличивают баланс до фактической даты операции. Для 29–31 числа в коротком месяце выбирается последний день.

Пополнение цели создает связанную операцию и уменьшает баланс счета. Накопленная сумма второй раз не вычитается. При удалении пополнения деньги возвращаются на счет. Изменение суммы корректирует копилку. Для удаления цели сначала удалите ее пополнения.

Создание долга — запись обязательства: оно не меняет баланс и не отражает первоначальную выдачу/получение денег автоматически. Если это нужно, внесите такую операцию отдельно. Нажмите «Внести платеж» и укажите любую положительную сумму в пределах остатка. «Мне должны» создает доход, «Я должен» — расход. Общая сумма долга сохраняется; остаток равен общей сумме минус все связанные платежи. «Весь остаток» заполняет сумму последнего платежа. После полного погашения статус меняется автоматически. Исправление или удаление платежа пересчитывает остаток; удаление может снова открыть закрытый долг. Историю можно открыть на карточке. Общую сумму долга нельзя уменьшить ниже уже погашенной.

## Ежемесячные шаблоны

В «Планы» есть отдельные разделы «Подписки и регулярные расходы» и «Постоянные доходы». Например, стипендию достаточно создать один раз: сумма, число месяца, категория, счет и дата начала. Каждый месяц создается отдельная операция.

По умолчанию у нового шаблона включена автозапись. Она срабатывает при открытии приложения, возвращении к нему и раз в минуту, пока приложение открыто; во время редактирования формы обработка откладывается. Если приложение было закрыто, при следующем запуске добавятся наступившие месяцы начиная с заданной даты. В фоне при полностью закрытом приложении операции не создаются. Будущие даты не записываются заранее.

В ручном режиме на карточке есть кнопка «Записать»: можно уточнить сумму, дату и счет за текущий месяц. Повторная запись того же месяца защищена от дублей. Удаление операции из истории сохраняет отметку об обработанном месяце, поэтому она не появится снова автоматически; при необходимости восстановите запись обычной операцией.

Сохраненные операции независимы от шаблона. Изменение суммы, счета или категории действует на еще не записанные месяцы. Удаление шаблона прекращает будущие повторения и сохраняет все прошлые доходы/расходы с их суммами, датами и заметками.

При переходе со старой версии существующие подписки сохраняются в ручном режиме, чтобы не создавать неожиданные расходы. Откройте карандаш на карточке и включите автозапись, если она нужна.

## Сброс офлайн-кэша

В «Настройки → Обновление приложения» есть кнопка «Сбросить кэш». Сначала проверяется доступность свежей версии, затем удаляются только статические файлы Потока и регистрация его Service Worker. Финансовое хранилище, счета, цели, долги и резервная копия не очищаются. После проверки приложение перезагружается на текущем экране.

При отсутствии сети сброс не выполняется, чтобы не лишить вас офлайн-доступа. Это отдельная операция от «Очистить базу», которая действительно удаляет финансовые данные.

## Данные и приватность

База использует формат версии 2; старые JSON версии 1 и локальные данные обновляются при чтении с сохранением операций и балансов. Данные сохраняются в `localStorage` под ключом `potok.finance.v2`. Предыдущее состояние — в `potok.finance.v2.backup`. Старый ключ `potok.finance.v1` читается и переносится автоматически; отдельный новый ключ защищает обновленную базу от перезаписи старой вкладкой. При повреждении основной копии приложение пытается открыть резервную. При недоступности хранилища или переполнении оно показывает ошибку и не сообщает об успешном сохранении.

База привязана к **адресу сайта и браузеру**. Локальный запуск, GitHub Pages и размещенная версия имеют отдельные базы. Для переноса используйте экспорт/импорт JSON. Очистка браузера, приватный режим или потеря устройства могут удалить записи. Хранилище не зашифровано.

Приложение не отправляет финансовые записи на сервер. Для первого подключения Chart.js и Lucide браузер обращается к CDN; затем Service Worker пытается кэшировать библиотеки. Если CDN недоступен, локальные SVG-иконки и резервные представления диаграмм сохраняют работоспособность. Полноценные графики Chart.js доступны после успешной загрузки библиотеки.

Офлайн-режим требует хотя бы одного успешного запуска онлайн и завершения установки Service Worker. Установка PWA зависит от браузера; встроенный браузер некоторых приложений может не поддерживать ее. Предпочтительны актуальные Chrome/Edge на Android и Safari на iOS.

## Структура

```text
index.html      оболочка приложения
styles.css      адаптивный интерфейс
app.js          экраны, взаимодействия, сохранение, импорт/экспорт
finance.js      финансовая логика и проверка данных
manifest.json   конфигурация установки PWA
sw.js           кэш статики и работа без сети
pwa.js          безопасный сброс кэша
icon.svg        значок сайта
icons/          PNG-иконки PWA и maskable-иконка
```

При выпуске изменений обновляйте `CACHE` и список `CORE` в `sw.js`, метку версии и URL стилей/модулей в `index.html`, а также версии импортов в `app.js`. Это сохраняет совместимость оболочки, финансового модуля и офлайн-кэша. Новая версия интерфейса загрузится при следующем открытии/перезагрузке.

В архив включены проверки финансовых расчетов и PWA. Если установлен Node.js, запустите `node --test tests/*.test.mjs` из папки приложения.

Используются [Chart.js](https://www.chartjs.org/docs/latest/) и [Lucide](https://lucide.dev/), распространяемые по MIT. Документация [Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers).
